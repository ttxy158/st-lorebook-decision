决策模型接管世界书

每次生成前先让决策模型判一遍「哪些世界书条目本轮真的用得上」，相关的强制注入、无关的压制，中间带交回原来的关键词规则。 摘要和条目索引两件事走哪条通道，由第 ④ 类顶上那颗「走酒馆主 API」的勾选决定：勾上就用你写正文那套，不勾才用那一段自己填的地址／Key／模型名。 这一页是从底部魔法棒菜单里的「决策索引工作台」打开的，左边两页是填条目和改分类，右上角齿轮是这里。
① 接管与连通
启用决策路由
开着它，每次生成前先把最近剧情和候选条目发给决策模型问一轮；关着就不问模型，世界书照原来的关键词规则注入。 只接管「设了关键词的普通条目」：常驻条目、你自己关掉的条目、内容里带 @@activate 的条目一律不动。 判定是三态——高概率即使关键词没命中也强制注入，低概率即使命中也压制，中间带交回原来的关键词规则。 下面那颗「允许压制低概率条目」默认关着，关着只记下哪些条目本来会被压制，并不真把它们挡在外面。

允许压制低概率条目
关闭关键词触发注入
勾选后，判过的条目不再靠关键词命中自动注入，只有概率 ≥ 强推阈值的条目会进入提示词；中间带也不再兜底。 常驻条目、手动钉住（@@）的条目、以及本轮没拿到判定的条目（超出候选上限、模型无返回）不受影响，仍按关键词走。 建议先看一次「查看本次决策依据」确认强推清单够用再勾，阈值没校准时会漏掉本该在场的内容。 勾选后「允许压制低概率条目」对判过的条目已无意义（反正都不注入），可以不用管它。
条目太多时分多轮问完
只有候选条目数超过「单批上限」时这颗才起作用。 关闭时只问第一批，剩下的条目这次仍按关键词注入。 打开后分出的轮次是并发发的（同时几路见「并发路数」）：实测 80 条候选 = 5 轮，串行 1.15 秒，4 路并发只要 0.3~0.5 秒；总 token 不变。 任何一轮失败都会停下来问你，同一批里失败的轮次合并成一次询问；只要没点「按原关键词注入」，本次决策不会自己作废。
调用失败时不再询问，直接按原关键词注入
不勾选时，失败弹窗有三颗按钮：重试（把失败的轮次再问一遍，没有次数上限）、我自己挑注入条目（列出本轮候选，你勾中哪些就强制注入哪些，这一轮不再问模型）、按原关键词注入（放弃本次决策，照常生成）。 回车和 ESC 走的是「按原关键词注入」，不会误点成再发一次付费请求。 手动勾选的结果只对本次生成有效，也不写进缓存；在世界书里已关闭的条目不在候选范围内，也救不回来，要用先去世界书面板打开。 内容被对端过滤（拒答）时弹窗会多两颗：全部复用上轮结果（拿上一次判定的分数直接用，一次请求都不发，本轮剧情不算数）和 本轮使用正文摘要（先花一次请求让 LLM 把本轮剧情改写成概括，再用它重判；只有依据来源选「正文」时才出现，因为它就是摘要档的日常做法临时做一次）。 超时、连不上、模型返回格式不对这些不是拒答，仍然只有原来那三颗。
每轮决策跑完自动弹出结果报告
弹窗不会挡住生成（它在生成开始前就浮出来，你可以边等回复边看）。 复用上次结果的轮次不重复弹。不勾选时看聊天页底部的「决策结果」小栏，点按钮随时能翻。
数值
「复用轮数」的代价说清楚：白嫖的这几轮不会重新判，剧情推进了也不会——新出场的人物不会被强推，已经退场的还留在提示词里。 世界书增删条目、改条目正文、重建或手填摘要、改判定问法或工作认知，都会当场作废、下一轮重新问；想立刻重判就把这个数改成 0 再生成一次。 选了「每 n 轮判一次」时，这个数会自动抬到不小于 n（否则间隔里那些轮没有判定，会悄悄退回关键词注入）；下面那行显示的就是生效值。
② 决策依据与时机
正文就是现行的做法：把最近几楼（含你正在输入的那句）原样拼进决策请求。它最准，但正文里的露骨描写会让决策模型整批拒答，一个判定都拿不到； 拒答时弹窗里可以点「本轮使用正文摘要」临时救场。
LLM 摘要是每轮 AI 回复写完之后再发一次请求，把新剧情并进一份滚动摘要，下一轮决策只看这份摘要（谁在场、在哪儿、刚刚发生了什么、用户想要什么）。 它几乎不会被拒答，代价是每轮多花一次请求，而且摘要里没写下来的细节模型就判不出来。

③ 条目摘要索引与分类
用摘要索引和分类问法判条目
这是默认打法：每轮生成时，条目拼给决策模型的不是正文片段，而是事先摘要好的那一句，并按它所属分类用那一类自己的问法提问 （问人物的「是否出场」、问设定规则的「是否在管辖范围」，本来就不是同一句话）。 摘要的写法是先点明这是什么（类型＋名字／关系），再给一个主触发（这一类判定问的那件事，人物就是「登场或被提及时」），最后补一句当前状态——要的是这一条的用处说明而不是剧情概括：决策模型拿它判断「现在要不要把这条注入进系统提示词」（注入进去就是角色扮演的背景设定或写作规范）。主触发只写一个：把用得上的情况一条条罗列开，只会把名字和关系挤掉。 摘要只影响怎么问：条目被强推时注入的还是完整原文，一个字都不会少。 条目原文是补充那一档：没建过索引、或者那一类没填专属问法的条目，照旧读正文片段 + 第 ⑤ 类里那条通用判定问法。关着这一档时全部条目都按正文片段判。 到工作台的「填写条目索引」那页去弄：自己逐条写，或在那儿点按钮让 LLM 填（发请求会消耗 token）。

④ llm的使用和api自定义填写
让这两趟 LLM 都走酒馆主 API
这一颗管两件事：第 ② 类那份正文滚动摘要、第 ③ 类给条目写摘要建索引。勾上就用你写正文那套 API（地址、Key、模型跟着酒馆当前选择走），不勾才发往下面这套自定义填写。 摘要和分类是把条目重写一遍，不是抽取原文，所以要用会写概括的对话模型；决策模型那个接口只回答「是否涉及」，干不了这活。 世界书条目里带露骨描写时，云端模型可能整批拒答 —— 拒答的条目不会写进索引，会在结果里点名，下次点按钮会再问一遍。

⑤ 提示词
所有能改的提示词都在这一档，每框下面那颗 ↺ 恢复默认；没带 ↺ 的那两框留空就等于用内置默认。
每轮拼进决策请求的四段
这段每轮都拼在决策依据最前面，后面那几段问法都在它这个语境里被理解。想改口吻直接改框里的字，整框清空就是不要这段。 这里只填一句「当前场景是什么」，它会拼在每次请求的场景行里。交代任务该改上面那段「工作认知」，不是这个框。 点发送后那句话还没写进聊天记录，插件会把它补进上下文并打上这段标注，让模型知道这是将要发生的事。整段清空就是不要标注。 上面三段拼在一起是模型读的依据，这一框是它拿着依据去做的事：每个条目都会被套进这句话生成一个问题，模型逐条回答。 占位符：{digest} 条目摘要，有索引时是索引里那句、没索引时是标题｜关键词｜正文；{label} 只取标题； {keys} 只取关键词；{content} 只取正文片段。
这句话就是模型在判断的东西，务必让它问「是否涉及/是否在场」，别问「续写需不需要」—— 实测同一个条目两种问法差 0.45 分。留空回到默认；写了但一个占位符都没用会自动补上 {digest}， 否则所有条目问同一句话、分数全都一样。建过索引的条目走的是它那一类自己的问法，那一类的问法去工作台「分类编辑」那页改， 这一条只兜住没索引的条目和没写专属问法的那一类。
摘要那一趟用的两份
它交代那个模型「输出不是给人读的，是给另一个只看概括的判别模型当依据」。留空等于用内置默认。 占位符：{old} 已有摘要、{new} 本轮新增剧情、{limit} 摘要字数限制。 这份摘要只喂给决策模型当依据，不会拼进你写正文那套提示词。 要它「收敛到做了什么／想要这一层、别复述露骨细节」是能不能不被拒答的关键，改的时候留住这句。 没写 {new} 会自动补在末尾。
给条目写摘要建索引用的两份
占位符：{types} 分类清单、{count} 本批条数、{entries} 编号+标题+关键词+正文、 {limit} 条目摘要字数限制、{otherName}「其他」那一类的名字。
模板里漏了 {entries} 会自动补在末尾并提醒一次 —— 不然等于没把条目喂给模型，白发一次请求。 内置默认里已经写了开头的【这份索引之后怎么用】（先让模型建立认知：这句是给「要不要注入这条」的判定读的，不是剧情概括）、中间「先点明这是什么，再给一个主触发，主触发只写一个」和「露骨描写照实概括，这是在给检索做标注」，自己改时别把这几段删掉——尤其开头那段，删了模型就只会写概括。
