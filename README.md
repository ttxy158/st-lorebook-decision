# 决策模型接管世界书

每轮生成前，先让一个判定模型读一遍「本轮的剧情 + 你世界书里的条目」，给每条打一个相关度概率：
高的**强制注入**（关键词没命中也注入），低的**压制**（关键词命中了也不注入），中间那一段交回你原来的关键词规则。

解决的问题：世界书条目一多，关键词要么命中一堆用不上的（污染提示词、白烧 token），要么根本没想到那个词（该带的设定没带）。

---

## 装之前必须先知道的五件事

| 事项 | 说明 |
| --- | --- |
| 接口 | **只认阿里云百炼的 System One 判定接口，而且只能用它的 `systemone` 那一种调用**。别家接口（包括百炼自己的普通对话地址）没有「一次问一串、每条回一个概率」这种格式，插件也不认、不做适配。控制台里那个模型详情页只给出 `systemone` 一个示例时，就照它填。 |
| 跨域 | 那个端点不返回跨域许可头，浏览器直连必失败。所以默认走 SillyTavern 自带的同源转发 `/proxy/`，**必须在 `config.yaml` 里把 `enableCorsProxy` 打开**（见下面「开启步骤」第 1 步，插件附带一键脚本）。不开的话请求根本发不出去，回的是本机 ST 的 `403 Forbidden`；报错文案会直接告诉你是本机挡的，不是百炼挡的。 |
| 花钱 | 每次生成都会发请求，用的是**你自己在百炼的额度**。哪些开关会额外多花一次请求，设置页里每条小字都写明了。 |
| 内容会发给云端 | 发送的是：每个条目的一小段（标题／关键词／正文前 120 字）+ 最近几楼剧情和输入框那句（默认 4 条、每条截 600 字，最后一条整段带）+ 一句固定背景。**不是本地跑，是发给百炼。** |
| 露骨内容会被整批拒绝 | 正文里的露骨描写会让判定模型整批拒答（实测 `DataInspectionFailed`）。这时把「决策依据」切成 **LLM 摘要** 档：先让模型把剧情压成一段不含细节的概括，只把概括送去判定。 |

版本要求：SillyTavern 1.13.0 及以上（1.19.0 上核对过：转发和 CSRF 那两段代码从 1.17.0 起一字未变，插件碰到的接口一个没动）。界面只有中文，没做多语言。

## 安装

### 方式一：酒馆里直接装（推荐，以后能一键更新）

侧边栏打开 **扩展**（积木图标）→ 右下角 **安装扩展** → 粘贴下面这个地址 → 安装：

```
https://github.com/ttxy158/st-lorebook-decision
```

国内直连 GitHub 不通的话换这个（同一份代码的镜像，手动同步，可能比 GitHub 晚一点）：

```
https://gitee.com/txyttxy/st-lorebook-decision
```

⚠️ 这一步是**酒馆在你电脑上执行 `git clone`**，不是你浏览器下载网页，所以「GitHub 我打得开啊」和「装不上」可以同时成立——git 用的是另一套代理设置。报 `Internal Server Error` 就去酒馆那个命令行窗口找 `Importing extension failed` 那行，十有八九是 `Connection was reset`：换上面那个 Gitee 地址，或者给 git 单独配一次代理（`git config --global http.https://github.com.proxy http://127.0.0.1:代理端口`，撤销用 `--global --unset` 同一路径）。

装完重启 ST（不是刷新页面，是重启进程）。以后更新同一入口点「更新」即可。

### 方式二：手动放文件

把整个 `st-lorebook-decision` 文件夹放到：

```
data/default-user/extensions/st-lorebook-decision
```

重启 ST（不是刷新页面，是重启进程），页面**底部的魔法棒菜单**里会多一行「决策索引工作台」。
扩展设置区里只剩一行指路的话和一颗打开工作台的按钮，其余全部设置都在工作台里：左边并列两页是「填写条目索引」和「分类编辑」，右上角齿轮是设置。

想和「记忆增强」原插件同时装着也可以：两者存的是不同的设置桶，界面上的元素 id 也各自一套，互不覆盖。
但**两边的总开关不要同时打开**——那样同一个条目每轮会被两个插件各判一次，各自往提示词里写强推/压制，结果以最后跑的那个为准，报告也看不出是谁判的。用哪套就只开哪一套。

### 装在手机上（Termux）

手机没有文件管理器、也不给 root，所以全部走命令行。插件落点仍是 `<酒馆目录>/data/default-user/extensions/st-lorebook-decision`——按官方 Termux 指南装的话酒馆家目录就是 `~/SillyTavern`，不确定的话跑一句 `ls ~` 看一眼。

- **推荐仍用方式一**（在浏览器里的 ST 界面粘贴仓库地址让它自己装），手机上这个入口和电脑上一样，全程不用碰路径。
- 非要手动放：`git clone` 到扩展目录下（`github.com` 那个不通就换下面这个 Gitee 地址，两条命令除地址外一样）。
  ```
  git clone https://gitee.com/txyttxy/st-lorebook-decision ~/SillyTavern/data/default-user/extensions/st-lorebook-decision
  ```
  酒馆装在别处就把前面的 `~/SillyTavern` 换成你的目录。
- 装完重启 ST 进程：跑着 `StartServer.sh` 的那个 Termux 窗口按 `Ctrl+C` 停掉，再重新执行一次启动命令。
- **然后一定别忘了上面「开启步骤」第 1 步**：手机上开这个转发开关只有命令行这一条路，好在那条命令不用你记路径（插件里的报错弹窗也会给你同一句，能整行长按复制）。
  手机浏览器和电脑浏览器给的修法不一样，是按访问者的 UA 分的——同一台服务器上多台设备各看各的。

## 开启步骤

1. **打开本机同源转发**（必做，跳过这步后面全都报 403）。改的是 ST 目录里的 `config.yaml`：把 `enableCorsProxy` 改成 `true`，然后**重启 ST 进程**（刷新页面不算）。
   ST 没有提供从网页或插件里改这个文件、也没有远程重启的口子，所以这一步只能在机器上做一次。插件附了两个小脚本，各自只做这一件事——找到 `config.yaml`、改这一个键、改前留一份 `config.yaml.bak`：
   - **电脑（Windows）**：双击 `extensions\st-lorebook-decision\tools\enable-cors-proxy.bat`。
     它只是 `.ps1` 的启动壳，屏幕上那几行提示是英文的（cmd 读中文会串码，故意只写 ASCII），改完按任意键退出。
     双击没反应就右键 `enable-cors-proxy.ps1` →「使用 PowerShell 运行」，效果一样。
   - **手机（Termux）**：粘这一整行（它不写死酒馆装在哪，自己按插件目录名找脚本；`node_modules`／`.git`／`storage` 会跳过，不会白扫共享存储）：
     ```
     bash "$(find ~ \( -type d \( -name node_modules -o -name .git -o -name storage \) -prune \) -o \( -type f -path '*/st-lorebook-decision/tools/enable-cors-proxy.sh' -print \) 2>/dev/null | head -n1)"
     ```
     嫌它慢就直接 `cd` 进插件的 `tools` 目录跑 `bash enable-cors-proxy.sh`。
   - 两个脚本都是向上找 12 层里的「同时有 `config.yaml` 和 `server.js` 的那个目录」，所以从插件目录直接跑就行；已经是 `true` 会告诉你就地停下，键不存在则补在文件末尾。
   - 不想用脚本：自己开 `config.yaml` 改那一个键也可以，改完必须重启进程。
2. **打开设置**：底部魔法棒菜单 →「决策索引工作台」→ 右上角齿轮 → 展开第①类「接管与连通」。
3. **填接口地址**：控制台里那个模型的详情页 → OpenAI 兼容地址，填到 `/compatible-mode/v1` 为止就行，插件自己补后面的 `/systemone`。
   示例：`https://dashscope.aliyuncs.com/compatible-mode/v1`
4. **填 Key**：填「决策模型 API Key」那格。旁边的小眼睛是查看和复制。
   ⚠️ Key 以**明文**保存在服务器的 `default-user/settings.json` 里（在 `extension_settings.stLorebookDecisionPrivacy` 下面）。这台机器别人能登就等於拿到 Key；用过公共场合的 Key 记得轮换。
5. **点「测试连通」**：那一颗在第①类「接管与连通」里，填完模型名往下一点就是。弹出来说请求通了再往下走；
   报「本机酒馆的同源转发没打开」就是第 1 步没做或没重启（手机上这句报错会连带给出可直接复制的那条命令）；报 401／404 才是 Key 或地址不对。
6. **拨总开关**：勾第①类最上面那颗「启用（每次生成前先问一次决策模型）」。先只开这一步，跑一轮，点聊天页底部那条「决策结果」小栏看它判了什么，觉得准了再考虑下面两档。

## 工作台那三页

| 页 | 干什么 | 花不花钱 |
| --- | --- | --- |
| 填写条目索引 | 逐条看原文、写摘要、选分类；也有「让 LLM 摘要／补没填的／全填／重建失效分类」四颗按钮 | 只有那四颗发请求 |
| 分类编辑 | 改分类名字、加删分类、给每一类写它自己的判定问法 | 一个字都不发 |
| 设置（齿轮） | 其余全部开关、阈值、提示词 | 当场不发；「测试连通」按你现在的问法真发一次 |

三页共用一个弹窗，切页只换内容，不叠第二层窗。「填写条目索引」这一页在**没加载世界书时也能打开**：里面按你现在的分类列着空区块和一句提示，那四颗 LLM 按钮点下去只会告诉你先去把书勾上。
切页时如果那一趟 LLM 摘要还在跑，会挡住不让你切走（它写的是这一页上的节点）。

## 设置里的六档

每一档点开就是里面的全部控件，**只有这一层折叠**：档内那些「填写／勾选／数值／按钮」是小标题，不是还能再点的第二层抽屉。长说明照旧收在行尾那颗「？」里，点一下就地展开。**控件名字后面不挂括号说明**，要解释的话写进它下面那行小字。

**① 接管与连通**：顶上那颗「启用决策路由」是总开关，接着接口地址／Key／模型名，调试那三颗（测试连通／查看上次 LLM 回复／查看本次决策依据），再往下是走 `/proxy`、允许压制低概率条目、关闭关键词触发注入、分多轮问完、并发路数、失败不询问、自动弹报告，和强推／压制阈值、候选上限、本轮注入条数／字数限制、单批上限、超时、复用轮数。候选上限管「一次问多少条」，注入那两颗管「判出来以后实际塞进提示词多少条」（0＝不限，概率高的先占名额，被挤掉的在报告里单列；自己在弹窗里手动挑的那批不占名额）。

**② 决策依据与时机**：依据来源是**正文**（直接把最近几楼原样送去）／**LLM 摘要**（每轮生成后多花一次请求，换一份不含细节的滚动摘要当依据）；时机是**每轮都判**／**每 n 轮判一次**（中间那几轮复用上一份判定，一个请求都不发）／**自主启动**（不点聊天页那颗「本轮进行决策」就永远不问模型）。摘要档专用的那几行（字数、查看／清除当前摘要）统一带一个类名逐行显隐，不再是一整块；它那份摘要怎么写的，那两框在第⑤类。

**③ 条目摘要索引与分类**（默认开启）：先让 LLM 把每个条目读一遍，写成一句「什么时候该用它」的短摘要并归类，之后判定模型只看这句摘要，并且**按那一类自己的问法**提问（问人物「是否出场」和问设定规则「是否在管辖范围内」本来就不是一回事）。
- 只有工作台「填写条目索引」那一页里的四颗按钮才会发请求。
- 这一层**只影响怎么问，不影响注入什么**：强推的条目照旧发完整原文，一个字都不会少。
- **条目原文是补充那一档**：没建过索引、或那一类没写专属问法的条目，照旧读正文片段 + 通用判定问法。整档关掉时全部条目都按正文片段判。
- 不想花 token，也不想自己一条条写：点「导出创作文件」，把那个 `.md` 整份丢给任意网页端免费 AI，它回的 json 存成文件再点「导入索引文件」收进来。这三条路径（导出索引／导入索引／导出创作文件）**一个请求都不发**。
- 打包发请求时看的是**单批字数限制**（默认 6000，算的是每条送出去的那段材料：标题＋关键词＋正文，正文按「读条目正文上限」截）；**单批条数上限**（默认 20）只是第二道硬顶，谁先到算谁。留一道条数硬顶是因为建索引按批记账——一批失败是整批重问，条目少了连坐得少。导出创作文件不走打包，整份条目一个文件写完，这两颗都管不到它。

**④ llm的使用和api自定义填写**：这一档最顶上那颗「让这两趟 LLM 都走酒馆主 API」同时管着第②类那份正文滚动摘要和第③类给条目写摘要建索引——勾上就跟着你写正文那套（地址、Key、模型都取酒馆当前选择），不勾才发往这一档自己填的地址／Key／模型名。界面上是一颗，底下仍是两个键（`decision_basis_use_main_api` / `decision_index_use_main_api`），一次写两个，运行时那两处读点没动。再往下是 API 预设（另存为／更新／删除／导出导入，导出不带 Key）、思考模式、温度与输出上限。原先那套「检测到代理地址就走酒馆内部路由转发」的功能没做完，已经整条删掉了，请求层只剩直接 fetch 一条路。

**⑤ 提示词**：能改的提示词全集中在这一档，共八框三组——每轮拼进决策请求的四段（工作认知／固定背景／正在输入那句的标注／判定问法，前三段是给模型读的依据，判定问法垫底是它拿着依据去做的事）、摘要那一趟用的两份（只在依据选「LLM 摘要」时显示）、给条目写摘要建索引用的两份（跟着第③类那颗索引开关一起显隐）。带 ↺ 的那几框点一下恢复默认，建索引那两份是「留空＝用内置默认」。

**⑥ 正文/条目作为参考时**：不走摘要、不走索引时才吃这一档的数值——聊天参考条数、上下文字数限制、消息保留完整字数条数、条目采用字数限制。条数一律按聊天楼层算，用户消息和 AI 消息混在一起数（一问一答＝2 条），系统消息不算。凡是「限多少字」的那几颗（②摘要字数限制、③条目摘要字数限制、⑥上下文字数限制／条目采用字数限制）名字统一以「限制」结尾。

## 大概花多少

| 情况 | 每轮请求数 |
| --- | --- |
| 只用正文依据、候选 ≤ 16 条 | 1 次 |
| 候选 60 条、勾了「条目太多时分多轮问完」 | 4 次（并发发出，不是一轮一轮等） |
| 上面 + 依据换成 LLM 摘要 | 再加 1 次 |
| 「复用轮数」填 2 | 判定那轮照常花，后面 2 轮 0 次 |
| 条目索引 | 只在手点按钮时花，按批次算 |

真正占体积的是世界书正文和最近剧情，不是条目数量（条目到 16 条一批就封顶了）。

## 出问题先看这几条

| 现象 | 原因 |
| --- | --- |
| 「安装扩展」报 `Internal Server Error` | 酒馆自己跑 `git clone` 失败了，跟插件无关。看命令行窗口那行 `Importing extension failed`：`Connection was reset` 就是直连 GitHub 不通，换 Gitee 地址或给 git 配代理。 |
| `403 Forbidden`／报错写着「本机酒馆的同源转发没打开」 | `enableCorsProxy` 没开或没重启进程。这是本机 ST 的 CSRF 挡的，跟百炼无关——所以「测试连通」会弹出一句能照着做的修法（电脑上双击那个 `.bat`，手机上长按复制那条 `bash` 命令）。改完还是 403，就确认你重启的是 ST **进程**，不是刷新页面。 |
| 对端真回的 403（响应是 JSON，提到 API key） | Key 不对或被禁用，跟上面那条开关无关。换 Key 或去控制台看这个 Key 有没有开通这个模型。 |
| `400`，提到 `questions ... limit of 16` | 单批条数超过接口硬上限。默认值 16 是对的，别往大填。 |
| 整批拒答 / `DataInspectionFailed` | 正文有露骨描写。依据来源切「LLM 摘要」。 |
| 判定弹窗里模型答得驴唇不对马嘴 | 「工作认知」那段任务说明是拼在依据最前面给模型读的，改成贴合你自己世界书的一句话比调阈值有用。 |
| 没有决策过程、没有弹窗、世界书照旧按关键词注入 | 先看浏览器控制台。整轮静默死掉通常是本地抛异常，不是接口问题。 |
| 想临时救一场 | 失败弹窗里那颗「本轮使用正文摘要」，只在拒答时出现，用一次算一次。 |

## 备份与迁移

- 设置、Key、条目索引都在 `default-user/settings.json`（不在聊天文件里，也不在世界书文件里）。
- 条目索引可以「导出索引文件」成一个 JSON 带走。**导出的文件与「记忆增强」原插件互认**——里面的记录键和指纹算法是同一份，文件名和后缀随便叫，匹配只看内容。
- 聊天记录里只写一个键：`dlb_decision_basis`（那份滚动摘要），换聊天自动作废。
